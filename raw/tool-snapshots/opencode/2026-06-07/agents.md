# 全局用户偏好配置

## 语言偏好
- 默认使用中文交流
- 代码注释使用英文(除非项目另有规定)

## 工作风格
- 简洁输出，避免冗余解释
- 先分析后行动，不盲目修改
- 每次修改必须验证结果
- 复杂任务使用Plan模式

## 代码风格偏好
- 倾向函数式编程风格
- 优先使用现有解决方案而非重写
- 保持最小改动原则

## 禁止事项
- 不要添加不必要的注释
- 不要做"预防性"重构
- 不要创建过早抽象
- 不要在未经用户同意时推送代码

## 工具使用偏好
- 优先使用专用工具(Read/Edit/Glob/Grep)而非Bash
- 并行执行独立任务
- 使用TodoWrite追踪复杂任务进度

## 上下文管理规则

### 核心原则: 上下文是稀缺资源

1. **精准引用原则**
   - 使用 `@filename` 精准加载文件，而非全量读取
   - 只读取必要的代码段，使用 `offset` 和 `limit` 参数
   - 避免连续多次读取同一文件

2. **搜索节制原则**
   - 使用Glob而非无限制的Bash find
   - 使用Grep而非Bash grep/rg
   - 设置 `head_limit` 限制搜索结果数量

3. **压缩时机原则**
   - 上下文超过150K tokens时主动建议 `/compact`
   - 完成大任务准备开始新任务时建议 `/compact`

4. **清空时机原则**
   - 切换到完全不同的任务时建议 `/clear`
   - 当前任务已彻底完成时建议 `/clear`

5. **并行vs串行原则**
   - 独立任务并行执行(多个Glob/Grep同时调用)
   - 依赖任务串行执行(先读取再修改)

### 反模式警示

| 反模式 | 后果 | 解决方案 |
|--------|------|---------|
| Kitchen Sink Session | 上下文污染 | 一事一议，做完/clear |
| Infinite Exploration | token耗尽 | 限制搜索范围，用Subagent |
| Whole File Reading | 空间浪费 | 只读必要部分 |
| Duplicate Reads | 重复占用 | 一次读取，记住内容 |

## 安全优先规则

### 危险操作黑名单

**禁止的Bash命令:**
- `rm -rf /` 或任何无确认的批量删除
- `git push --force` (未经用户明确授权)
- `git reset --hard` (未经用户明确授权)
- 任何修改全局配置的命令
- 任何涉及credentials/secrets的命令

**禁止的代码修改:**
- 不删除安全检查代码
- 不绕过认证逻辑
- 不添加硬编码密钥
- 不移除错误处理

### 代码安全审查要点 (OWASP Top 10)

1. **注入漏洞**: 检查SQL/命令注入
2. **XSS**: 检查未转义的输出
3. **认证问题**: 检查会话管理
4. **敏感数据**: 检查加密和存储
5. **访问控制**: 检查权限验证

### 用户确认要求

以下操作必须先确认:
- 删除文件或分支
- 推送到远程仓库
- 修改共享配置
- 创建PR或Issue
- 发送外部消息

## 工作流程最佳实践

### 标准流程: 探索-计划-执行-验证

```
探索阶段 → 计划阶段 → 执行阶段 → 验证阶段 → 提交
```

### TDD工作流
1. 用自然语言描述功能需求
2. 生成测试用例(Plan模式)
3. 确认测试用例后生成实现代码
4. 自动运行测试，不通过则自动修正
5. 所有测试通过后提交代码

### Plan模式触发条件
- 涉及>2个文件改动
- 架构级变更
- 数据库迁移
- 安全相关修改
- 重构任务

---

## 代码质量要求

### 必须执行
- 修改后运行相关测试
- 代码格式化(prettier/eslint)
- 类型检查(tsc --noEmit)

### 推荐实践
- 编写单元测试覆盖新功能
- 添加必要的类型定义
- 保持代码风格一致性

---

## 错误处理规范

### 报错信息要求
- 粘贴完整的Stack Trace
- 说明预期行为和实际行为
- 提供复现步骤

### 禁止行为
- 只说"报错了"
- 截断错误信息
- 隐藏关键错误细节
