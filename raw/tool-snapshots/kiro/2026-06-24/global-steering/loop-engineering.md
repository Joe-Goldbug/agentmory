# Loop Engineering — 四闭环执行框架

> 不是提示词集合，是 4 个可重复执行的闭环。
> 每次工作默认按顺序：sync → truth → execute（project 或 bugfix）→ verify → write back。

---

## 统一执行顺序

```
sync loop        → 确认上下文一致
truth-first loop → 验证事实，不瞎猜
execute          → 进入 project loop 或 bugfix loop
verify           → 改完必验证
write back       → 更新状态到对话记忆
```

最短记忆版：**先同步上下文 → 先验证事实 → 一次只做一个最小任务 → 改完必须验证 → 最后写回状态**

---

## 1. Truth-First Loop

**目标**：先确保"不说错"，再追求"做得快"。是所有 loop 的总门禁。

**循环**：

1. 读取当前任务、上下文、相关文件、已有状态
2. 把关键判断分成四类：
   - **verified fact** — 已验证
   - **inference** — 有依据但未验证
   - **assumption** — 无依据的假设
   - **unknown** — 不知道
3. 对代码、配置、日志、部署、路径、权限、数据问题 → 先看真实源头
4. 如果关键事实未验证：
   - 不下结论、不直接执行
   - 明确标记"未验证"
5. 如果证据冲突：
   - 先指出冲突点
   - 先核实，不跳过冲突继续编造解释
6. 输出本轮决策边界：
   - 已验证什么
   - 推断了什么
   - 还不知道什么
   - 本轮改什么 / 不改什么
   - 怎么验证结果

**停止条件**：关键事实已足够支撑执行，或因证据不足转为人工判断。

**一句话规则**：默认目标不是"回答得像对"，而是"尽量不说错；不能确认时明确说未验证"。

---

## 2. Project Loop

**目标**：让产品和项目按最小闭环稳定推进，不靠临时对话推进。

**循环**：

1. 读共享全局习惯和项目状态
2. 确认当前阶段：Idea / MVP / Launch / Scale
3. 只选当前唯一最高优先级任务
4. 明确本轮边界：
   - 解决什么
   - 不解决什么
   - 成功标准是什么
5. 拆成一个最小可执行动作
6. 执行
7. 验证结果
8. 写回状态（对话记忆中更新）：
   - 当前状态
   - 关键判断
   - 下一步
   - 验证结果

**停止条件**：本轮最小任务完成并验证通过，或遇到需要人判断的边界问题。

**一句话规则**：一次只推进一个明确任务，不做大而全并发扩张。

---

## 3. Bugfix Loop

**目标**：持续修 bug，但不让修复系统失控。

**输入**：报错、测试失败、日志、复现步骤、代码上下文

**循环**：

1. 收集证据
2. 判断是不是有效 bug
3. 分类：
   - **Tier 1**：可直接修（根因明确、范围小）
   - **Tier 2**：先调查再修（根因不确定、需要更多证据）
   - **Tier 3**：必须人工判断（影响大、方向不确定）
4. 明确根因判断
5. 限定修复范围：一个 bug → 一个根因假设 → 一个最小 patch
6. 执行修复
7. 跑验证门：
   - V1：编译 / 静态检查通过
   - V2：测试通过
   - V3：变更范围检查（没改不该改的）
8. 记录结果：成功 / 失败原因 / 下一步建议

**停止条件**：
- 修复验证通过
- 同一问题连续失败 3 次 → 停下来重新分析根因或升级为 Tier 3
- 范围扩大或进入 Tier 3 → 请求人工判断

**一句话规则**：没有证据，不进入修复；没有验证，不算修好。

---

## 4. Sync Loop（Kiro 独立模式）

**目标**：保证每次对话开始时上下文一致、状态可恢复。

> Kiro 不主动同步 iCloud 文件，但遵循相同的 Loop 执行顺序。

**同步层分工**：

| 层 | 内容 | Kiro 对应 |
|----|------|-----------|
| 全局层 | 工作习惯、AI 规范 | `~/.kiro/steering/*.md`（本文件等） |
| 项目层 | 项目状态、决策、下一步 | `.kiro/steering/*.md`（工作区级） |
| 对话层 | 当前任务状态 | 对话上下文记忆 |
| 本机层 | 权限、凭据、缓存、本地运行状态 | 不同步 |

**循环**：

1. 对话开始时：读取全局 steering + 项目级 steering
2. 确认当前项目状态是否连贯（上次做到哪、什么决策、下一步是什么）
3. 如有不一致：先标出差异，以 steering 文件为准
4. 执行任务
5. 任务结束时：关键决策和状态变更反映在对话中（如需持久化则更新 steering）

**停止条件**：
- 全局 steering 已读取
- 项目状态连贯
- 当前任务状态已明确

**一句话规则**：不追求同步整台机器，只追求同步"习惯 + 状态 + 决策 + 下一步"。
