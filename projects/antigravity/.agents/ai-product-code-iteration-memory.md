# AI 产品代码迭代记忆规范 (.agents/ai-product-code-iteration-memory.md)

本规范定义了在 **Loop Engineering** 体系下，如何通过项目级记忆文件维持多端设备间“状态与习惯”的一致性，确保无论是同一设备的不同会话，还是跨设备开发，AI 都能完美继承前文。

---

## 1. 记忆文件结构
所有迭代记忆文件统一存放在项目根目录的 `.memory/` 文件夹下，包含五个核心文件：

| 文件名 | 作用 | 归属 Loop | 更新频率 |
| :--- | :--- | :--- | :--- |
| `session.md` | 记录全局用户画像、偏好、禁忌和全局只读知识库路径 | Sync Loop | 仅当偏好/全局设定改变时 |
| `STATE.md` | 追踪当前项目所处的生命周期阶段与当前状态 | Project Loop | 每次任务开始与结束 |
| `DECISIONS.md` | 记录过程中的所有关键技术选型、架构与设计决策 | Project / Bugfix Loop | 做出关键判断时追加 |
| `NEXT.md` | 定义下一轮迭代或修复的唯一最高优先级最小可执行任务 | Project / Bugfix Loop | 任务结束时写入下一步 |
| `VERIFY.md` | 记录每次代码修改后的具体验证手段与测试结果 | Bugfix / Project Loop | 代码修改后，写回前更新 |

---

## 2. 核心文件维护指南

### A. session.md
- **核心目的**：让进入项目的 AI 瞬间明确“我是谁（代码小白的伴侣）”、“我需要遵守什么特殊习惯”。
- **必要内容**：
  - 用户画像（例如：代码小白，需通俗易懂）。
  - 穷尽探索原则（永不放弃，使用除破坏系统/删除文件外的一切手段实现目标）。
  - 禁忌（例如：禁止盲目猜测，禁止大范围重构）。
  - 全局 Wiki 路径引用。

### B. STATE.md
- **核心目的**：记录“我们在做什么，当前在哪个阶段”。
- **生命周期阶段划分**：
  - `Idea`：想法阶段，讨论可行性与架构。
  - `MVP`：最小可行性产品开发阶段。
  - `Launch`：部署发布与上线阶段。
  - `Scale`：重构、性能优化与规模化迭代阶段。
- **当前状态**：用一两句话准确描述最新版本的发布状态或当前阻塞点。

### C. DECISIONS.md
- **核心目的**：记录决策的“病历卡”，避免 AI 方案反复、推倒重建。
- **书写格式**：
  ```markdown
  ### [YYYY-MM-DD] <决策简述>
  - **决策内容**：具体做出了什么决定（例如：选用 Vanilla CSS 替代 Tailwind）。
  - **背景原因**：为什么做这个决定，解决了什么痛点。
  - **影响范围**：哪些组件或模块受此影响。
  ```

### D. NEXT.md
- **核心目的**：防止 AI 发散任务、做大而全的并发扩张。它规定了本轮的“绝对终点”与下一轮的“绝对起点”。
- **规则**：
  - **有且仅有一个**当前处于 In-progress 或待办状态的核心任务。
  - 必须包含清晰的边界（解决什么、不解决什么）。

### E. VERIFY.md
- **核心目的**：贯彻“没有验证，不算修好/做好”的硬性门禁。
- **书写格式**：
  ```markdown
  ### [YYYY-MM-DD] <验证任务名称>
  - **验证项**：要验证什么功能/Bug 修复。
  - **验证手段**：具体测试命令、运行日志片段、浏览器测试结果等。
  - **结果**：[通过 ✅ / 失败 ❌ ] 附带具体数据或表现。
  ```

## 3. 跨设备同步 (Sync Loop) 动作规范
当我们在不同 Mac 或终端之间切换时，AI 必须严格执行以下 Sync 动作：
1. **读（Sync In）**：启动新会话的第一步，依次读取 `.agents/AGENTS.md` -> `.agents/ai-product-code-iteration-memory.md` -> `.memory/session.md` -> `.memory/STATE.md` 和 `.memory/NEXT.md`。
2. **定（Truth-First）**：对比当前本地实际代码状态，确认是否与内存文件一致，有冲突先指出。
3. **写（Sync Out / Write Back）**：
   - 任务完成且验证通过后，将执行结果和下一步计划更新回 `VERIFY.md`、`STATE.md`、`DECISIONS.md` 和 `NEXT.md`。
   - 绝不带着未写回的记忆结束会话。
